# 14 · 族群扩展草案（未启用）

状态：**设计草案，未进入冻结契约。** 参考裁判、`content/core_pack.json` 和黄金向量都不执行本章。数字是未实测建议，不能写成平衡已验收。

本章是旧三局点数规则的未启用草案，不是现在的回合战。现行规则在 `docs/01_GAMEPLAY.md`。下面的文字保留，供对照旧的 `pcg.core.v1`：10 张牌、最多 3 个小局、每小局最多打出 5 张、可以停手、比整数总战力。本章当年只提议在那套骨架上增加「配对」。

研究原文在 `research/`。95 条硬件记录不是 95 张卡，74 条候选也不是已经采用的卡表。

## 1. 建议就这一套，不并列多套规则

若以后要做扩展，采用下面这一套，不要和「双行动」「免费装备」「扣血」混用。

- 每张牌，包括随从、器具和战术，都占 10 张牌里的 1 张，打出时占 5 次里的 1 次。研究稿里「一体机占 2 次行动」会改掉「最多 5 张」的含义，本草案不采用。
- 配对在打出时看已经在场的牌，结成一次，不回头改已经结成的结果，也不让一张牌再触发别的牌。
- 换脸是例外：小局结算前看整组面板一次。两张写着同一块地址牌的面板同场时，架子和这两张面板的配对都取消。基础战力保留。这样不会谁先打出谁占便宜。
- 一条链路上的链式配对合计最多 +2。一名玩家本小局全部配对合计最多 +3。超出的部分从后结成的配对里去掉。
- 胶囊信使在场时，只保留第一次器具或随从配对。
- 少出一张、常客的「没有配对就 +1」、小墨屏、轨上表和灯墙的结算加分，都在配对上限算完之后另算，不叫作配对。
- 过载示警若已打出，对方的配对上限改为 +2。
- 小局结束清场，配对一起结束。本草案没有中途让宿主离场。同名在牌组里仍然最多 1 张。
- 未知组合：不配对。官方点名结构合不上：不配对。两种情况都不扣基础战力，不写烧毁。

研究稿里的负分、热瞳镜无人时改按另一套分数、以及把随从免费贴在英雄上，都不采用。

## 2. 硬件事实怎样变成羁绊

证据状态留在研究表里。`high` 表示读过对应产品页或教程里的明确句子，不是实验室插拔。`medium` 多半只说明官方目录、历史页或地址索引里看得到。目录没有穷尽产品线。带斜线的行是复合记录，不能当成已经逐个验证。

### Core2 与底座

Core2 产品页禁止和 **Base 系列功能底座**叠装，理由是内置震动马达和这类底座结构干涉，并建议拆下原电池底、改用 M5GO Bottom2。这是对 Base 系列的警告，不是「凡是底盘都不能用」。

Faces Bottom3 自己的页面写明可以接 Core1 / Core2 / CoreS3，并接面板。它不是那条 Base 禁令点名的普通底座。草案因此：

- 厚壳 + 厚底板：可以配对。底板是换下原来的电池底。
- 厚壳 + 普通底：不配对。普通底只代表研究里的 Base 系列复合行。
- 厚壳 + 脸架子：可以配对。没有把家族禁令盖过 Bottom3 的明确支持，也不把未写明的缝隙写成损坏。

### 其他已核过的边界

- StickS3 用 Hat2-Bus。官方点名结构不兼容的是 Mini JoyC U156、Mini EncoderC U157、18650C U080。其他经典冠对 StickS3 **未知**，草案不配对，也不写成禁配。
- 官方仍把 StickC-Plus2 写成能配 HAT。麦克风和帽子可能共用一条线，所以帽子只加 1，不是禁配。游戏里的对应角色叫自带电。
- 功放冠是 I2S，只和加长刃配对。
- Grove 不是任意口都能用。回声锤要细口（I2C），回声钉要宽口（GPIO）。外观相同的 Chain 线是 UART 链，不是 Unit。
- 定位模块要按主控对好位置。火头若已经和定位针同场，之后的定位模块不加；先打出的模块不追回。
- 键帽脸和手柄脸是同一块地址牌。算盘脸的地址未知，不强迫冲突。面板上的辅助芯片不是英雄。
- M5-Bus 的电源脚位置固定，其余脚随宿主变化。交互式堆叠工具本轮没有逐条导出，没导出的组合保持未知。
- 链节听双头指挥，或听已经坐下「接上串」的小块指挥。两种小块的默认脚不同，接上串负责把脚对上，不因此再加一次分。

## 3.1 千里眼为什么建议改成器具

现行卡 `unit_cam_scout` 的显示名曾经写成 Unit Cam。核对官方页面 https://docs.m5stack.com/en/unit/unit_cam ：产品名是 Unit CAM，SKU U109，主控 ESP32-WROOM-32E，传感器 OV2640，用 UART 或 Wi-Fi 传图，也能运行自己的程序。它是插在宿主上的摄像头单元。

它不是 UnitV、UnitV2、TimerCamera，也不是 Unit CamS3。研究目录里的 U012 把好几款相机写在一行，不能拿来替换这张卡。

能自己跑程序，只说明原始表要保留这件事，不说明它在游戏里必须当英雄。它的现行技能是盯住对面一个单位并让战力 -2。这更像一件侦察器具。草案因此把设计类型写成器具，英文名 Lookout，中文名千里眼。效果数字、一次出牌都不改。

`content/core_pack.json` 里它的 `template_id` 和单位类型没有改，内容哈希也不变。现在打开游戏，它仍按角色结算。表格里的「现行类型」和「设计类型」必须同时看得见，不能只改其中一个却假装已经降级。

CardputerZero（官方文档名 CardputerZero，SKU C154 / C154-B）不在这 95 条里，本草案不给它战力。它是 Linux 口袋机，不是上面的敲键。

机器可读的同一份名单在 `content/expansion_draft.json`，字段 `document_status` 为 `design_draft_not_enabled`。

## 4. 例牌

基础教学 10 张不变，不需要任何草案卡：厚壳、探子、细条、旋钮、存页、帮腔、敲键、立岗、加一把、压一下。

草案牌组仍然是 10 张，用来看取舍，不是已平衡套牌。

**叠层。** 厚壳、火头、常客、厚底板、普通底、温湿计、定位模块、加一把、压一下、少出一张。普通底便宜，但经常不加分，只是占一张牌。

**细棍。** 细条、长条、自带电、新细条、测距帽、小摇杆、小喇叭、细条小屏、电池帽、压一下。小摇杆在细条上更厚，在新细条上只剩自己的 3 点。小喇叭只认长条。

**换脸。** 厚壳、脸架子、键帽脸、手柄脸、算盘脸、厚底板、磁铁靠近、少出一张、加一把、压一下。键帽脸和手柄脸不要一起打。

**串线。** 探子、新小块、接上串、双头、一节键、一节灯、串线舵机、往回传、少出一张、压一下。接上串要先于链节。不要指望两头加成相乘。

## 6. 先认识哪一族

先打基础 14 张，确认留牌和停手。然后只加一族：细棍最容易看出「同一族也不一定配对」，换脸最容易看出「多一张可能更差」，串线最容易看出顺序。小块的接上串，要等链节已经存在再理解。其余出身是新的配法，不是更贵的分数。

作者注：以后若要按所选出身装入文字，只需基础公共牌加这一族。玩家界面不要出现资源包或 DLC 字样。这里不设计固件和下载服务。
