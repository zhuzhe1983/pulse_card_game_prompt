# 07 · 验收矩阵、恢复与发布门槛

本章是交付判定。包内 reference 测试只证明规定输入下的逻辑与字节契约；不能代替真卡断电、射频丢包、平台权限或应用商店分发验收。发布时必须区分 PASS / FAIL / NOT_TESTED / NOT_APPLICABLE，并附可复现步骤。

## 1. 玩法验收

| ID | 场景 | 必须结果 |
|---|---|---|
| G01 | 9/11 张、重复模板、少于 6 单位 | 开局前拒绝，无半初始化战局 |
| G02 | 初始状态 | 每人 10 手牌、0 分、两排空、第一先手 = seed & 1 |
| G03 | 非当前玩家/旧 revision/非法排 | 整个动作拒绝，手牌/分数/revision 不变 |
| G04 | 无目标 BOOST 单位 vs 战术 | 单位可部署且跳效果；战术不可打 |
| G05 | 存在目标却传 null | 拒绝；不能绕过技能选目标 |
| G06 | stable 被 +2/-2；shield 被两次 -2 | stable 不变；shield 第一次抵消并消耗，第二次实际扣分 |
| G07 | 减到 0 分 | 单位仍在排内，仍是目标并满足另一排存在条件 |
| G08 | SELF_BOOST_OTHER_ROW | 只在入场时检查一次；同排没有加分；不能反复旋转/重连触发 |
| G09 | 第 5 张投入为战术 | 同样消耗投入并自动 PASS |
| G10 | 已 PASS 一方 | 本小局不能再出牌；对方可连续行动到 PASS/上限 |
| G11 | 小局转换 | 已出牌进弃牌，未出牌保留，不补牌、不复活 |
| G12 | 先后手 | 胜者下局先；平局切换原先手，和最后操作人无关 |
| G13 | 胜/平/胜组合、空手局 | 2/1 积分与至多 3 局正确；剩余空局自动结算，不卡死 |
| G14 | 两端重复同动作 | 只执行一次；同 action_id 改内容报冲突 |
| G15 | 对手/旁观者视图 | 看不到隐藏手牌、牌组、NFC 身份和收藏数据 |

## 2. 卡片与存档验收

| ID | 场景 | 必须结果 |
|---|---|---|
| S01 | 未登录刷英雄卡 | 不发奖、不写账本；提示先登录 |
| S02 | 登录后首次刷有效盲盒/固定卡 | 模式正确；结果、领取账本、快照一起本地提交 |
| S03 | 同卡同日反复停留/移开刷 | 同一领取最多一次；不是每个读卡回调都奖励 |
| S04 | 卡 ID 相同但 pool/app 版本改变 | 仍已领取；不因更新重置 |
| S05 | 次日/其他玩家刷同卡 | 按定义可领取；设备本地时区切换不构成新游戏日 |
| S06 | 没有绝对时间/回拨至旧游戏日 | 可对战；领取阻止并说明原因；不把 uptime 当日期 |
| S07 | 提交前断电/提交后展示前断电 | 前者重试同结果；后者恢复已领取，不重复发奖 |
| S08 | 本机 S3，玩家卡 S0，已知同源 | 使用 S3；玩家卡字节不改变，显示未导出 |
| S09 | 新设备只有卡 S0 | 只能载入 S0；不能因知道 player_id 偷偷拿 A 的 S3 |
| S10 | 显式再刷同玩家卡 | 冻结导出快照→写全→回读→验 hash 成功才标记已迁移 |
| S11 | 保存时刷成别的玩家卡/英雄卡 | 拒绝写入，保持本机数据；不得覆盖别人的账号 |
| S12 | 容量不足/拔卡/权限失败 | 明确失败，不标成功，不抹掉本地进度；原卡可恢复性按 profile 如实说明 |
| S13 | RAW_DUAL 每个写入字节处中断 | 老槽或完整新槽仍可选；不能选择 pending/坏 hash 槽 |
| S14 | NDEF_SINGLE 写入中断 | 不承诺旧 NDEF 仍完整；使用本机 pending export 与明确恢复流程 |
| S15 | A/B 分支；相同 UUID 不同内容 | 冲突备份，不自动加钱/拼账本/覆盖卡 |
| S16 | 未来存档主版本/未知必需字段 | 只读或拒写；不丢字段再覆盖 |
| S17 | UID 空/随机/端序不同 | 不登记为稳定每日卡；读卡报告暴露差异 |
| S18 | USB 键盘 UID 读头 | 只能如实报告识别；不得出现可写玩家存档的虚假成功 |
| S19 | 重复与外观兑换 | +10 碎片；50 解锁 ink；不修改对战属性，重试不重复扣钱 |

## 3. 通信验收

| ID | 场景 | 必须结果 |
|---|---|---|
| N01 | 同内容/规则 HELLO→READY | 确定相同 manifest hash 与 deck 才开始 |
| N02 | 缺 opcode、trait 或不同 hash | 无法 READY，解释需哪个包/客户端能力 |
| N03 | Float/重复 JSON key/非法 UTF-8/-0/超长 | 严格拒绝，未进入规则引擎 |
| N04 | COMMMAND 重复/超时再发 | 持久幂等，重启 authority 后仍不重复执行 |
| N05 | 旧 snapshot/旧 RESULT 后到 | 不回滚当前状态；可以 RESUME |
| N06 | WebSocket 分帧 vs 串口任意切分 | 还原同 envelope；不按回调次数计消息 |
| N07 | PCG-F1 乱序、重复、CRC 损坏 | 合法重组一次，坏片不确认，完整包后严格解析 |
| N08 | 最后一片 ACK 遗失 | 重传收到完整 ACK，不再次交付 |
| N09 | 同 index 不同 payload/越限/无限慢滴 | 拒绝并释放；有限缓存与截止时间 |
| N10 | 鉴权 token 伪造/seat 注入 | 无权玩家不能替别人行动；sender_id 自报不等于认证 |
| N11 | 连不上真实无线物理层 | 报能力不足/提供桥，不显示虚假联机 |
| N12 | 一局进行中内容更新 | 锁定原包，更新下局生效 |
| N13 | 未完成动作+断线重连 | 新 session、原 action_id/body、最新私有过滤 snapshot |
| N14 | 存在旧端仍支持 core v1 | 可以选共同冻结卡包；不必每次更新 app |

## 4. 目标平台真机检查

PaperMono：全灰阶可读、局部刷新残影清理、触控命中、真实读卡器任务不被屏幕刷新阻塞、flash 写入频率与断电恢复。Dial：圆屏不裁掉确认/PASS、旋钮聚焦可返回、每个公开单位都可查看、确认前没有实际出牌。手机：NFC 系统会话取消/后台/权限拒绝、读卡重新进入、网络切换、应用杀进程恢复。Web：明确浏览器和来源安全条件、IndexedDB 持久化结果、后台挂起、NDEF 能力和本地桥安装路径。USB/Grove：真实电源、引脚、波特率/I²C 地址、卡型、容量、读回与卡移开行为逐项验证。

性能目标要实测而非宣称：输入后 100ms 内提供可感知响应为目标（蜂鸣/高亮/等待文字均可）；电子纸完整图像刷新不强制 100ms；本地出牌逻辑不被动画阻塞；传输等待展示真实状态。首次目标报告附实际 heap/PSRAM/flash 使用，不套用其他板卡的数值。

## 5. 测试证据格式

每条验收记录：ID、客户端版本/commit、ruleset、content_hash、设备/OS/浏览器/读卡器固件、步骤、预期、实际、结果、日志/照片路径、限制。真实 UID、玩家 token、完整私有卡数据默认脱敏。

交叉互测至少使用两个独立进程；发布“跨平台已验证”至少需两种不同客户端实现的同局输入/结果。单个程序里的两份状态模拟不是跨平台真机验证。对每次规则改动保存新的版本 fixture，不能覆盖旧规则历史。

## 6. 自动检查与人工边界

包内运行：`python -m unittest discover -s tests -v`。可选 Schema 检查：`python tests/validate_schemas.py`（需 jsonschema）。`VALIDATION_REPORT.txt` 记录本包实际执行结果。`reference/` 不包含真实 NFC/Wi-Fi/ESP-NOW/USB 驱动或完整游戏客户端；不能把该测试报告拿去替代设备交付报告。

发布阻断项：规则黄金向量不同、重复扣牌/发奖、隐藏手牌泄漏、保存失败显示成功、覆盖未来存档、双方内容不一致仍开局、无法说明真实 NFC 能力。视觉动画未完成、可选传输尚未实现可以明确列入限制，但不冒充核心功能完成。
