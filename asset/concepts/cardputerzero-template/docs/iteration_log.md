## 主体生成

GenerateImage，参考官方提取的 char PNG + CardputerZero 官方产品图。

### 风格 A

- v1：已有模切徽章框，但键盘画成 ADV 式白字键，屏上有 18:45 / LACK TAB。
- v2：黑键和扁平感改善，体态却变成竖方形。
- v3（采用）：恢复横向掌机，保留徽章框与黑椭圆键。仍有电源区残字（LACK TAB 等），屏上 ZERO 偏大，键帽未完全坐在白字符条上；主体是栅格而非纯矢量。

### 风格 B

- v1：横向浅灰一体机、白描边、无投影、无外伸 USB，眼睛对比不足。
- v2：眼睛变白，但体态变成竖向手机。
- v3（采用）：保持 v1 体态，眼睛改为白圆。仍偏“设备插画”而不是 CORE 那么极简的脸；键位数少于实物 46 键。

去底：先用全局绿色阈值，误删了屏上青绿 ZERO 和部分浅色。改为**从画布四角洪水填充**与背景连通的绿幕像素，内部 ZERO/白眼得以保留。边缘做绿色溢出抑制。源图是 JPEG，不能无损。四角 alpha 为 0；白边外圈偶有 JPEG 毛刺。

CairoSVG 默认不加载外部 `file://` 图，曾渲染出“只有模板没有角色”。后改为 PNG data URI 嵌入，并注明主体不是纯矢量。

B 角色最初在正方形槽里垂直居中，脚离开阴影。改为 `xMidYMax meet` 后落在原椭圆上。

## B 标题

`CARDPUTER ZERO` 用本机 Oswald Bold 排出，比原 `CORE` 更长，因此槽位比原稿标题框更宽。原稿 CORE 字母是转曲路径，新标题**不是**原字形。固定层口号未改。

## 校验（CairoSVG，同渲染器）

见 `validation/compare_report.json`：

- A/B 模板对比：diff_pixels = 0
- 完整卡在 char 槽（及 B 的标题槽）之外：diff_pixels = 0

遮罩是官方 char bbox 与标题 bbox 的并集，不是整卡大矩形。

## 2026-11-10 16:05 Asia/Shanghai — 排版/去字确定性修正（未重画整卡）

按用户目视反馈：模板方法正确，但 B 动态标题有黑色重影，A 主体右上有 LACK TAB 等生成乱码。本轮不重新生成主体，只改合成。

### B 标题

原先用两个 `<text>`：黑色字号更大并向下向右偏移，白色叠在上面，所以白字细、黑底更宽，出现双层轮廓。已改为 Oswald variable 实例化到轴最大值 wght 700，fontTools 转成字形路径，**同一 `d` 先画黑色圆角描边、再画白色填充**（每行各一对 path，无 `<text>`）。标题约束在原稿 CORE 槽 `[42.207, 190.863, 110.863, 215.346]`，排成两行 `CARDPUTER` / `ZERO`，避免单行 14 字撑破槽位盖住黄胶囊或角色。描边居中，可见描边宽度约为 stroke 的一半。

**新标题字体不是 100% 源转曲一致**：原稿 CORE 是 CDR 转曲四字锁闭，源字体未嵌入；Oswald 是替代面，也不是原字形路径描摹。两行是为了把长名装进原四字槽，不是源文件版式。不要因为模板 0 像素差就认为动态标题没有视觉问题——上一版重影与模板差分无关。

### A 乱码清理

在去底后的 char PNG（906×642）上局部去字，不是重画外观。去掉 LACK TAB，并尽量去掉电源区 POWER SWITCH / USB C2 / 5V ONLY CHG；LACK TAB 原位置换成两枚无字深色圆角按键。保留灰壳、黑键、青蓝机械徽章、透明底，以及 CARDPUTER ZERO / ZERO / Python / STORE / CLI / M5STACK 和橙色摇杆（含按钮上的 ON）。固定层未改。清理后电源区会留下一块较平的修补色，局部仍可能残存极淡笔画像素；这不是产品关键名称，也没有重画整机。

### 校验（CairoSVG 638×1004）

隐藏新槽后 vs 源模板：A/B **diff_pixels = 0**。完整卡在官方 char bbox 与（B）原标题 bbox 之外：**0 像素差**。已去掉先前为过宽标题准备的扩大遮罩。0 差分只证明固定层未被改动，不能代替对动态标题的目视检查。
